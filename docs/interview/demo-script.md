# Demo script

## Five-minute portfolio walkthrough

Use synthetic accounts in separate browser sessions and a disposable workspace.

1. In the first minute, follow the dashboard count into Needs review and explain the next step.
2. In the second minute, accept the report as Reviewer, then claim, start and complete it as Member.
3. In the third minute, reload the Reviewer session and show the assignee and dated completion history.
4. In the fourth minute, show the saved refresh checkpoint and the closure notice screenshot.
5. In the final minute, show the browser matrix and restore evidence. Identify the local measurements and pending hosted checks.

Keep verification links, invitation proofs and credentials outside the recording. Use the case study introductions and system diagram for the architecture discussion.

## Slice 1

1. Register a synthetic account and open the verification link from the local inbox.
2. Sign in, create **Northline Tools**, set Dark appearance, and reload the workspace.
3. Open its URL in another verified account. Show the unavailable screen and explain the 404.
4. Return to the Owner session, sign out, and show that visiting the workspace URL redirects to sign-in.
5. Show the automated browser test and point out the session-expiry integration test.

## Slice 2

1. Open **Team** as the Owner. Invite Mara as a Reviewer and Jules as a Member.
2. Open each link in a separate browser context. Confirm the invited email and accept to show the assigned role.
3. Change Jules's role and then remove Jules. Reload the already-open Team page from that account to show the loss of access.
4. Transfer ownership to Mara. Show the Owner controls in Mara's session after reload, then leave from the former Owner session.
5. Explain the seven-day boundary, repeat acceptance and transfer-versus-removal tests. Keep the invitation proof off screen once it's served its purpose.

## Slice 3

1. Preview and connect a public repository from the Owner view. The local test fixture offers `northline/cli`.
2. Open **Repositories** as Reviewer and refresh. Point out the examined count, imported count, and the last successful refresh.
3. Open the **Triage inbox**, select a report, and point out the **Needs review** and **GitHub Open** labels.
4. Show the Member's read access, then explain the page, checkpoint, and rollback test.

## Slice 4

1. As Mara, accept **CLI crashes on Windows** with High priority and a concrete next step.
2. As Jules in a separate session, open **Available to claim**, read the next step, and claim the issue. Use **My work** to start it and mark it **Done**.
3. Reload Mara's session. Open **All issues → Done** and show Done, GitHub Open, Jules's assignment, and the dated completion entry.
4. Explain how the transaction resolves two competing claims and how the command ID makes a lost response safe to retry.

## Slice 5

1. Ask Jules which Windows version reproduces the issue. Use Jules's browser session to answer from My work.
2. Return to the Reviewer session and show Needs review with the preserved question and answer.
3. Accept the issue, then draft a next-step edit. Change the priority in another authorized session. Show the newer priority and the intact draft after attempting to save.
4. Explain how the author can review the saved decision before choosing to submit their draft again.

## Slice 6

1. Use the three-page `northline/refresh` fixture. Start the refresh as Owner and close the tab after the first committed checkpoint.
2. Open Repositories as Reviewer. Show the saved count and select **Resume refresh**. Open the inbox and show one issue from each of the three pages.
3. Use the integration scenarios to show what the saved snapshot does after a timeout, confirmed loss of access, or a verified transfer. Point out the retained workspace decision.

## Slice 7

1. Open the overview and select **Available to claim**. Compare the dashboard count and the inbox total.
2. Open an assignee's workload, search for a qualified issue number, and open the result with the keyboard. Use Back to show that the search and selected row are restored.
3. Use the `northline/workload` fixture to refresh a closed GitHub assignment. Open the Member session and follow the notice to the filtered **My work** queue.
4. Show the matching workspace activity and the 5,000-issue timing report.

## Slice 8

1. Show the previous image, candidate digest, additive migration, and readiness response.
2. Revert to the previous image and open the candidate's saved triage decision and history.
3. Open the restore evidence and walk through encryption, isolated restore, membership reconciliation and public-source revalidation. Point out the separately measured snapshot age and time to safe access.
